7. Frontend Design System — Addressing Calendar UI & Learning Curve
7.1 Design Tokens & Accessibility
Color palette: High-contrast with WCAG AA/AAA compliance. Use a 12-color categorical palette for job types/assignees, each with a distinguishable text label (not just color).
Typography: Inter for UI, system fonts for speed; fluid type scale with clamp().
Spacing: 4px base grid.
Dark mode: Native support with CSS custom properties.
7.2 Calendar UX Improvements
Multi-resource timeline view with horizontal lanes per crew/rep, drag-and-drop rescheduling.
In-calendar search (by job name, customer, assignee) with instant filtering.
Conflict detection with visual indicators and warnings.
Color encoding: Use both color and icon/shape to differentiate event types, ensuring color-blind users can distinguish.
Persistent filters: Save default view, date range, and filtered resources per user.
Performance: Virtualized day/week views to handle thousands of events without lag.
7.3 Guided Onboarding & Contextual Help
Interactive product tour triggered on first login, role-specific (sales vs admin).
In-app coach marks for first-time use of each module.
“Quick Start” dashboard with only 3 core actions for new small teams: Add Lead, Schedule Inspection, Create Estimate.
Documentation hub with short video tutorials and searchable help.
7.4 Mobile-First PWA
Offline-first: Service worker pre-caches shell and core data; mutations queue in IndexedDB and sync when online.
Performance: Code-split routes, lazy-load heavy modules; image compression using WebP/AVIF; limit animation.
Mobile-specific UI: Bottom tab navigation, large touch targets, camera-first photo capture, GPS location auto-fill.
Push notifications for job updates, feed mentions, and schedule changes.


8. Job Feed (Message Board Replacement)
A modern, real-time communication hub per job, accessible on all devices.
Features
Threaded posts with rich text (markdown support)
Mention users with @username (triggers notification)
Attachments: photos, documents, videos (preview inline)
Automatic system posts for job status changes, estimate approvals, material orders, etc. (audit log)
Search and filter by user, date, or attachment type
Email/SMS digest option for daily or weekly summaries
Permissions: view-only for field crews, full access for PMs
Implementation
WebSocket event feed.new_post pushes to all participants of the job.
Stored in PostgreSQL with proper indexing; attachments in S3.
Full-text search using PostgreSQL's tsvector.
Offline support: posts created offline are queued and synced.
